cwa_sunrise

The browser port of cwa_sunrise.py. One call to Taiwan CWA's A-B0062-001 dataset — a county and a date in, that day's sunrise / transit / sunset time and azimuth out, plus the length of the day. Unlike every other demo here this endpoint needs an API key, which is why it is a box on the form and not a constant in the source.

How it works, and what goes wrong — notes

The API key is free from opendata.cwa.gov.tw (register, then 取得授權碼); it looks like CWA-XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX. It is sent as the Authorization query parameter, not as a header — CWA's own convention, and the reason a plain <a> to the request URL works. This page stores it only if you ask: tick 記住金鑰 and it is kept in this browser's localStorage, so the next visit has it already filled in; untick and it is deleted immediately. Left alone, nothing is written anywhere and a reload means typing it again. Either way no cookie is set, it is never sent anywhere but opendata.cwa.gov.tw, and it never reaches a server of ours — there isn't one, this is a static page. Storage is per-origin, so both pages in this folder share the one entry and the published GitHub and GitLab copies remember separately. It is hidden in the field and masked in the URL below until you tick 顯示金鑰.

A wrong key looks like a network failure, not a 401. CWA answers a bad key with HTTP 401 Forbidden: Authorization key is not correct. — and that response carries no Access-Control-Allow-Origin header, though a successful one does. So the browser refuses to hand it to the page at all and fetch() rejects before the status can be read. If this page says the request was blocked, check the key first.

An empty answer is still HTTP 200. A county name that does not match comes back as success: "true" with locations.location: []; a date outside the published range comes back with the county present and time: []. Neither is an error, so the page reports the emptiness rather than throwing. The commonest cause is the wrong character: the API spells it 臺北市, not 台北市, and does not know the abolished 臺北縣 — hence the buttons.

timeTo is exclusive, which is why one day is asked for as timeFrom=D, timeTo=D+1; passing the same date twice returns nothing. Coverage runs about 2025-01-01 to 2027-12-31, and a window is capped at 180 records however wide it is asked for. This page only ever wants one day, so the cap is a note rather than a limit — but cwa_moonrise asks for three.

The line under the answer is what the script prints. 出:rise / azimuth, 中:transit / altitude, 沒:set / azimuth, then the daylight length in parentheses. Azimuths are degrees clockwise from north; the transit altitude carries an S or N suffix (76S) saying which side of the zenith the sun crosses — south of it, all year, everywhere in Taiwan except the far south around the solstice. The dataset also returns civil twilight (BeginCivilTwilightTime / EndCivilTwilightTime), which the script does not print; it is there in the JSON below.

This is a lookup, not a calculation — the numbers are CWA's, computed for the county, and this page only formats them. The repo computes the same quantities from scratch in pure_math/sun_phase.html, from a lat,lon and Meeus' series with no API at all; comparing the two is the point of having both.
