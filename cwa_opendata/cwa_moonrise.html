cwa_moonrise

The browser port of cwa_moonrise.py. Taiwan CWA's A-B0063-001 dataset over a three-day window, stitched into the one rise → transit → set cycle that starts on the day you asked for. Like cwa_sunrise it needs an API key, which is a box on the form rather than a constant in the source.

Why three days, and what goes wrong — notes

The moon does not keep to a calendar day. It rises about 50 minutes later each day, so on any given date one of rise / transit / set is missing from the record — an empty string in the response — or belongs to the day before or after. Asking for one day gives you a broken cycle roughly once a month per event. So the request covers [day−1, day, day+2) and pickMoonEvents() picks the cycle that starts on the target day, tagging anything borrowed with 昨 (yesterday) or 明 (tomorrow). The three records it chose from are laid out under the answer, and the line beside it names the branch that fired.

Two things stop a cycle being stitched, and only one is fixable. A transit or set stamped exactly 00:00 is the rounding of 23:59:xx — the end of that date — but compared as a string it sorts before every other time, which used to send the branching off to borrow from a neighbour that had no such event. orderKey() reads it as 24:00 for ordering only (never for a rise, which at 00:00 really is just after midnight), and those cases now resolve into complete cycles. What cannot be fixed is CWA simply having no time to give: it publishes an occasional wholly blank record — all three times empty, the angles still filled in — about once a synodic month at 澎湖縣, and very rarely two consecutive days with no rise. Those print as –, and the note under the answer says so.

The six branches, in the order they are tested. No rise today → it rose yesterday, and today's transit and set finish that cycle. No transit today → transit and set slip to tomorrow. No set today → only the set slips. Rise later than transit → today's transit and set belong to yesterday's cycle, so today's rise pairs with tomorrow's transit and set. Transit at or before set → an ordinary day, all three on the target date. Otherwise the set crosses midnight and is taken from tomorrow. The comparisons are on "HH:MM" strings, which sort as times because the fields are zero-padded.

The API key is free from opendata.cwa.gov.tw and travels as the Authorization query parameter, CWA's own convention. This page stores it only if you ask: tick 記住金鑰 and it is kept in this browser's localStorage, so the next visit has it already filled in; untick and it is deleted immediately. Left alone, nothing is written anywhere and a reload means typing it again. Either way no cookie is set, it is never sent anywhere but opendata.cwa.gov.tw, and it never reaches a server of ours — there isn't one, this is a static page. Storage is per-origin, so both pages in this folder share the one entry and the published GitHub and GitLab copies remember separately. It is hidden in the field and masked in the URL below until you tick 顯示金鑰.

A wrong key looks like a network failure, not a 401. CWA's 401 Forbidden: Authorization key is not correct. carries no Access-Control-Allow-Origin header, though a successful response does, so the browser refuses to hand it to the page and fetch() rejects before the status can be read. If this page says the request was blocked, check the key first.

An empty answer is still HTTP 200. An unmatched county comes back as success: "true" with locations.location: []; a date outside the published range leaves time: []. The commonest cause is the wrong character — the API spells it 臺北市, not 台北市 — hence the buttons. timeTo is exclusive, which is why three days are asked for as day−1 to day+2, and coverage runs about 2025-01-01 to 2027-12-31: at either edge the window comes back short and the page says so instead of stitching a cycle out of two records.

This is a lookup, not a calculation — the numbers are CWA's, computed for the county, and this page only stitches and formats them. The repo computes lunar altitude and phase from scratch in pure_math/moon_phase.html, from a lat,lon and Meeus' series with no API at all; comparing the two is the point of having both.
